# Shared implementation contracts

Frozen for initial P01/P03 work, 2026-09-18. Architecture remains authoritative; these names/boundaries resolve routine implementation choices.

- P00 supplies build integration and `core/version.hpp` only. Coordinator integrates shared build changes.
- P01 owns `core/error.hpp`, `core/bytes.hpp`, and `core/fixed_vector.hpp`: fixed-size `Error`/`ErrorCode`, `Result<T> = std::expected<T, Error>`, CPU-only `Bytes`/`MutableBytes`, and bounded move-capable storage. No formatted strings or allocation on core error paths. P01 also owns field identities, semantic packets and layout descriptors.
- P03 owns all memory/lease/provider types. `TxStorage` combines bounded segment references and external leases without depending on P04 completion. P05 composes storage with completion for transport submission.
- A semantic packet never owns or contains encoded transport buffers/leases. Immutable semantic snapshots must survive later builder edits independently.
- Byte spans convey CPU access, not ownership. Memory domains require explicit CPU-mapping checks. Retaining a view retains every distinct backing allocation; exposed handles remain move-only.
- P04 owns completion slots, publication protocol, reserved admission credits, executors, strands and the actual-size budget ledger. A completion result is not proof of device quiescence.
- Frozen candidates identify content hashes. Verifier tests/reports are independent of production edits; changes return through their implementer.

Later shared API additions require coordinator integration and revalidation of affected packages; this is not a new user-approval gate.

## P06/P09 planned and effective state boundary

Frozen for the baseline after P08 implementation, 2026-09-18. P06 owns creation of `include/vita/runtime/state/contracts.hpp`; P09 consumes it and owns revision/publication storage. The shared header depends on P01 semantic values and P08 timing types, not on transport or Context publication.

- `Validity { absent, known, unknown }`: absent means not supplied/applicable; unknown means an applicable value cannot be confirmed after an indeterminate result. Never substitute a numeric sentinel or silently retain an old known value for unknown state.
- `FieldState { FieldId id; SemanticValue value; Validity validity; }`; `StateSnapshot { uint64_t version; array<FieldState,4> fields; }`. Four slots are the explicit baseline capacity. Larger capacities may be distinct template types with separately validated budgets. Reading value requires known validity.
- `PlannedField` contains identity, requested and adjusted semantic values, a dependency mask over plan positions, eligibility, and diagnostic information. `ExecutionPlan` contains the bounded planned fields, expected state version, chosen `timing::Boundary`, operation identity and association generation. Requested/pending data never aliases mutable effective state. Dependency order must be acyclic and validated before effects.
- `FieldOutcome` carries identity; status (`executed`, `failed`, `cancelled`, `unknown_effect`, with explicit simulated tagging separately); resulting value/validity; actual `ProtocolTime` and sample ordinal with independent evidence-valid flags; and diagnostics. Executed does not imply timing success. A determinate failure preserves confirmed unchanged state; an indeterminate write marks affected state unknown. Hypothetical outcomes never become real effects.
- `EffectiveEvent` contains a coherent resulting `StateSnapshot`, actual effective time/ordinal evidence, source operation and association generation, and changed-field mask. P06 emits one immutable event per distinct real transition, including a real failure that invalidates knowledge of the state. It emits no event for dry-run predictions. Different effective times remain distinct events.
- The P09 effect sink receives a callback-scoped `EffectiveEvent const&` and copies it into already reserved revision storage. It does not execute setters or create a second command path. P09 wraps the event with revision ID/publication flags and enforces `sizeof(Revision) <= 512` for the baseline through a compile-time assertion.
- P06 performs validation, backend execution, completion consumption and coherent effective-state update; P09 performs revision/Context publication and Data gating. AckS observes current coherent state at its own observation time; it is not an archival requested-state or effective-time snapshot. AckX recording continues independently of Context transmission success.
- Async results use a bounded setup-owned result arena with a lifetime handle carried by every outstanding completion capability. The producer must win the P04 completion claim before writing its result record, then release-publish ready; the worker acquire-consumes the ticket before reading the record. `CompletionResult::value` may carry its record index/identity. Synthetic abandonment/timeout failure never reads an unwritten result record, and a stale/duplicate losing producer never touches record memory. A record is not reused before consumption, and outstanding callbacks cannot outlive its arena. This is independent of device-buffer quiescence.
- Admission must reserve worst-case revision transitions and result storage before device effects. Exact-rate timeline representability is validated on an isolated timeline copy before an actual rate write; rejection leaves the previous state unchanged.

## P06/P09 physical revision reservation

The final P06 interface reserves physical storage before side effects through `EffectSink::reserve`, returning a move-only `RevisionReservation` that pins its setup-owned arena. Unused reserved slots release through its callback. `EffectSink::record` receives the immutable event, the reservation, and a moved `AdmissionBundle` containing one revision and one Context-publication credit. Committed revision storage retains those credits until its dependent lifetime ends; releasing the originating transaction cannot revoke them. Queries and dry runs reserve no live revisions. `EffectiveEvent` includes the originating per-field outcome in addition to the coherent resulting state.

## P07 accepted cancellation identity

D-P07-1 is accepted by the user. Ordinary and cancellation meanings have separate records under the original full transaction key, distinguished by header L. Exactly one cancellation meaning is admitted over the original transaction's active and retained lifetime. Identical retries attach or replay; changed meaning cannot cause further cancellation effects. The retained cancellation result includes its original state observation and timestamp. The joint lifetime extends to at least 30 seconds after the latest terminal result and until references release. See architecture §6 and [decision record](P07-decision.md).

## Runtime completion storage partition

The runtime enforces a shared limit of 1,024 live completion reservations. Engines and transport submission may use separate setup-owned physical arenas; free backing slots are not live reservations. Startup charges every physical arena, including unused slots, in the exact memory budget and reports physical backing counts separately from the live admission limit. An admitted operation must acquire its global completion credit before it can submit a completion capability; failed admission rolls back both physical and logical reservations. Avoid charging twice when the transport itself acquires that credit. This permits bounded arena partitioning without changing the global admitted-operation limit.

## Clock corrections and temporal association safety

Derived implementation enforcement of architecture §§7–9: do not continue an association whose corrected mapping would reuse a wire-time interval already published under incompatible history. The generator tracks published Context event times and accepted Data intervals through each packet's last actual sample timestamp, using its frozen rate/count, not only packet start times, the mutable next-sample cursor, or local clock generations. If a corrected next timeline overlaps that domain, stop Data and require the existing coordinated `recover_stream` path with fresh paired SID and peer readiness. Normal start/resume cannot bypass this temporal-association fault. Preserve confirmed numeric device values for queries; uncertainty about temporal association does not itself make those values unknown.

This does not require a reset for every small negative PPS correction: a correction that leaves the next published timeline outside the used interval can be applied with checked arithmetic, preserving sample ordinal, rational residue and oscillator phase. Nonoverlapping mapping changes revalidate unarmed commands and gate newly mapped Data behind full Context. Accepted old packets retain their original metadata and lifetime; no same-SID receiver cache reset message is invented. This is conservative enforcement of existing association/recovery invariants, not a VITA-mandated reset rule. Supporting same-SID continuation across overlapping eras would require a separate future decision.
