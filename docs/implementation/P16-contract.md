# P16 tunable IQ profile and runtime contract

Status: frozen and approved by coordinator and independent verifier; production implementation authorized. This is the bounded dependency contract for the user-authorized frequency scan example, separate from P15/M6 hardware qualification. Array-of-CIFs stays excluded from operational packet decoding.

## Profile and compatibility

Add `profiles::iq::Profile { generator_v1, frequency_tunable }`, default `generator_v1`, to StreamConfig and explicit remote-target configuration. Existing transaction `Profile` gains `iq_frequency_tunable`; generic virtual register behavior stays separate. A single profile-to-class helper supplies information/packet classes to outgoing framing and exact route/class validation. Under the configured OUI, tunable information class is0x0002, Data classes0x0101/0102/0103 for IQ16/IQ32/float32, Context0x0110, Command/Ack0x0120. Existing v1 values stay unchanged. No automatic profile inference from a newly known CIF selector; a v1 route rejects tunable classes, and v1 commands carrying RF Reference Frequency remain unsupported. Fixture OUI is allowed only in explicitly isolated lab configuration. Trailer-enabled tuning is not advertised unless an explicit compatible trailer class is supplied, preserving current trailer policy.

RFReferenceFrequency (CIF0/27) means RF center, with IF and RF offset fixed zero by this profile. Range1,000,000..6,000,000,000Hz inclusive, exact integer-Hz grid. Fractional Q20 or out-of-range requests reject; there is no rounding/adjusted-frequency warning. The tunable profile SampleRate is queryable and fixed for its configured source session; runtime SampleRate writes are unsupported. A new explicitly configured/stopped source session may select another rate with a fresh scene phase epoch and association; no new wire reconfiguration protocol is claimed. Original IQ Generator v1 SampleRate writes remain unchanged. Mixed SampleRate+RF writes are rejected for the entire command before any effects, irrespective of partial execution. The sweep Controller never writes SampleRate; its configured rate is100,000Hz by default. Validation of a whole mixed plan precedes backend begin, including revalidation. A query may select both fields.

## Five state fields, four command fields

Introduce separately named `state_field_capacity=5` and `command_field_capacity=4`. Retain the existing first-four order and add RFReferenceFrequency at slot4. Preserve `baseline_fields` as the original four-field list; introduce `state_fields` for the five-slot lookup. `field_index` returns state capacity for unsupported IDs. Existing uint8 masks have enough bits. Wire CIF order places RF before SampleRate; every decoded field maps by FieldId, never by wire ordinal or presumed state slot. Define the profile enum/constants in a lean profiles/iq/profile.hpp without runtime/source dependencies, so StateSnapshot and higher-level profile APIs share one discriminator without an include cycle. Do not increase Request/ExecutionPlan/field-outcome-per-command/AsyncResult reservation arrays from4 merely because state grows. A five-field full Context is legal; a command may still select at most4 fields. Query-all convenience must split into bounded requests or not be offered.

StateSnapshot gains a profile discriminator and five FieldStates. Its RF slot is absent for v1 and generic virtual register, and known/unknown as appropriate for tunable. Construction and recovery validate canonical IDs, profile, semantic value alternatives/ranges and required validity. No loop sets every slot known indiscriminately. Shared `required_known` requires RF only for tunable; unknown tuning stops Data and requires the existing explicit known-state/fresh-association recovery path. Numeric query state remains distinct from temporal-association faults.

The discriminator is local typed metadata selected by the checked class binding, not a new wire field. ReceiverHistory/ContextReceiver receive an explicit configured profile; they cannot infer RF applicability from arrival order or simply trust a caller-set snapshot discriminator. Snapshot comparison, delta merges, initial/full/changed Context, initial validation and retained revisions cover all five slots. Unsupported extra RF in a v1 Context rejects; absent RF in a tunable full Context leaves required metadata incomplete. Old immutable received snapshots and retained leases remain unchanged.

AckRecord diagnostics and selected state masks are state-indexed and expand to5. ControllerRegistry requested/cancel selections, state capture/equality and query observation use the same five-slot map. Cancellation subsets still refer to the at-most4 selected command fields; dependency masks in ExecutionPlan refer to command positions, whereas backend validation dependency masks refer to five state fields. These two domains must not be conflated. Built-in VirtualBackend rules need five state-indexed entries; its pending capacity stays the configured transaction capacity.

## Public Controller and replacement-backend seams

Add `Controller::set_center_frequency(Hertz, CommandOptions={})`. Add `QueryField { reference_point, sample_rate, state_event, payload_format, center_frequency }` and `QuerySelection` constructed from an initializer_list<QueryField>, plus a checked `query(QuerySelection, CommandOptions={})` overload; retain existing numeric-mask overload for source compatibility but examples use names. Provide checked `StateObservation::value<Field>() -> Result<typename Field::value_type>` so example applications do not index internal arrays. For tuning, require terminal successful nonsimulated execution plus corresponding AckS known RF readback. AckV, transport acceptance, dry-run, partial/unknown outcome and an SDK write returning do not establish usable tuning. AckX/AckS may arrive in either order; retained observations satisfy the predicate only when both exist. Dwell begins at the local monotonic time that predicate becomes true. Timeout stops submissions; it never asserts the tune did not occur.

Existing Backend already separates validate/validate_plan/begin/simulate/disarm/quiescence and asynchronous FieldOutcome. Add a source-compatible optional public `DeviceBackendBinding` in StreamConfig: existing Backend callbacks, `shared_ptr<void> owner`, exact `storage_bytes`, and an optional bounded serialized `progress(context, OperationContext)` hook. Empty means existing built-in virtual backend. A configured binding must supply validation, begin and explicit quiescence callbacks. Missing simulate rejects dry-run as unsupported rather than fabricating a preview; missing disarm cannot claim cancellation or quiescence; missing progress means completion is driven externally while validation, progress of protocol state and ticket consumption remain Runtime-owned. Whole-plan validation is optional but profile-level mixed-write rejection is always mandatory. Declared owner/storage are validated and charged before runtime mutation. Store/pin the owner in the shared result-lifetime object so late capabilities cannot outlive device binding storage. Reject inconsistent shared-owner size declarations, and charge once per owner. Runtime polling calls the hook once per progress cycle and consumes tickets normally; it never calls virtual pending/complete/reinitialize methods for an external binding. Existing RecoveryConfig reinitialize callback supplies external known-state/quiescence evidence; absent evidence cannot be replaced with synthetic completion. Recovery preflight validates binding applicability before installing the new bank. No SDK or hardware implementation is part of P16.

For the virtual tuning backend, successful FieldOutcome carries actual RF, effective protocol time when qualified, sample ordinal and executed status at the effective usable packet boundary. It has zero physical settling delay. RF lock is not an extra invented VRT field; a future device must delay successful completion until its declared usable-sample condition is met and report actual value/time/ordinal or unknown/failure honestly. If usable effect cannot be mapped coherently to packet samples, Data stays gated; a guessed boundary is forbidden. The engine's existing effect event, revision reservation, Context acceptance gate and independent AckX path remain the single execution path.

## Remote endpoint binding

Current `add_controller(Controllee)` requires a same-runtime Controllee and install_association installs all four routes. Add `RemoteTargetConfig` and `add_remote_controller(RemoteTargetConfig)->Result<Controller>` with explicit profile, SID, short controller/controllee IDs, local/remote peer identities/generation, format, and optional checked Context/Data receiver binding. It is a controller-only endpoint: outbound Command counters and inbound Ack, optionally Context/Data, with no local request route, Engine execution, source start or claimed local device state. A source-compatible endpoint-role option lets separate-process Controllee install only its local Controllee routes while combined loopback retains both roles. Routine implementation may retain existing setup-allocated dormant bank objects initially, but must charge their real size and disable their effects; do not claim those objects absent from the budget.

Use the existing UDP factory. Each process needs only its actual directed PeerBinding: controller local_source→remote controllee, or controllee local_source→remote controller. TX matches local_source; RX matches configured remote address plus remote_source and route identity. Association preflight/commit must use only the endpoint's real direction. All lane addresses are explicit. Remote Controller shutdown stops submissions, drains/cancels using existing wire semantics as applicable, and releases local resources only after local transport proof; it cannot claim remote physical device quiescence. Detailed port/clock recommendations belong to P16-udp-readiness.md.

## Deterministic scene and timeline

Default scene: one absolute RF tone100,050,000Hz, amplitude0.5. Tunable center maps to baseband tone_rf-center_rf. Passband is exactly[-sample_rate/2,sample_rate/2); lower edge included, upper excluded. Out-of-band output is zero rather than aliased. Preserve tone and LO phase across tune boundaries and out-of-band periods; changing center changes future LO phase slope, not accumulated phase. At fixed integer sample rate, bounded integer modular phase accumulators avoid long-run ordinal/frequency-product overflow. Conversion to IQ uses existing normalized sample conversion and saturation rules.

The source must account for every active timeline sample, including packet drops/skips and zero-valued out-of-band windows. Freeze an optional SourceProvider effective-configuration callback, `Result<void> (*effective)(void*, const runtime::EffectiveEvent&) noexcept`, invoked serially for each real effective revision before later sample production. It is an observation of an already known real effect, not a second backend setter. A Runtime EffectSink fanout preserves the existing reserved revision commit and then notifies this source hook. Failure cannot retroactively falsify the backend outcome: it faults/gates the source and reports the existing real outcome. Dry-run, requested/pending state and mere Ack receipt never invoke it. Initial source configuration is supplied explicitly at ordinal0 before start; callbacks and source context follow the existing serialized provider lifetime contract.

The scene accumulates phase up to each effective ordinal using its previous RF center, then switches the future slope. Thus every intervening tune is observed even when no sample-production callback ran. At produce(first_ordinal), it advances any remaining gap with the last effective configuration, writes the window and advances exactly once. Events earlier than already generated samples, missing ordinal evidence for a running change, unknown RF, overflow or contradictory ordering fault Data rather than resetting phase or guessing. Stopped untimed configuration changes before sample creation are staged for the next initial known snapshot, without manufacturing effective timestamps. No hook invocation under a pool mutex and no unbounded history queue are needed. Test three centers100.025/100.040/100.065MHz effective at ordinals0/3/7 with tone100.05MHz and Fs100k: first resumed sample11 has phase0.55cycles, not the erroneous0.35 from integrating the newest center over the entire gap. Include suppressed out-of-band segments and reentry.

Sweep defaults are100,000,000..100,200,000Hz in25,000Hz increments,100ms dwell,1000ms command timeout and one finite sweep. Continuous mode is explicit. The fixed scene then demonstrates positive offset, DC, negative offset and both Nyquist edges. Separate-process applications drive progress with actual local steady time and a bounded poll loop; current virtual-clock-only run_for/wait are not used for wall-clock UDP operation. The isolated Controllee supplies ongoing explicitly simulated PPS updates, not a single mapping that silently expires after2s, and never labels this hardware GPS qualification.

## Recovery scene-epoch clarification

Independent end-to-end review found that a fresh wire association preserves the Runtime's absolute sample ordinal. Default `VirtualRfScene::create` remains strict about an initial ordinal of zero. Add the explicit `VirtualRfScene::create_for_recovery(SceneConfig)` factory for a newly authorized scene epoch: its first known, nonsimulated initial effective event establishes phase zero at the actual ordinal supplied by Runtime, including any recovery skips. It does not infer or integrate unknown prior phase. No samples may be produced before that event. Invalid RF/rate/ordinal evidence still rejects, and a faulted scene never silently rearms. Subsequent retunes and skipped samples obey the original continuous-phase rules.

The caller replaces the scene at its existing stable address inside `RecoveryConfig::reinitialize`, only after the backend's known-state and physical-quiescence proof succeeds. Runtime has paused that source before invoking the callback. Return true after the fresh scene is installed; the unchanged SourceProvider binding is copied into the fresh bank and receives its initial event at the actual retained ordinal. Do not call `set_source` from this callback: reentrant setup is rejected. Retain the scene holder throughout Runtime/callback lifetime, and use the explicit factory only with a fresh association; the scene helper cannot infer a wire era from an application reset.

Coordinator and independent verifier approved this clarification before helper implementation. It implements the already selected explicit recovery phase epoch without changing wire fields, ordinary tuning phase, IQ Generator v1 or the Runtime recovery API.

## Typed validation observation clarification

`Observation::validation_outcome_known` identifies usable AckV evidence; `validation_accepted` means whole, nonpartial admission with SchV set and no reported validation error, indeterminate state or negative timing outcome. False acceptance does not prove that no subset effects occurred. Neither field establishes actual execution or changes the existing execution-oriented `success` meaning. A late AckV retains its validation evidence and response kind while preserving the timeout and unknown execution outcome. Contradictory same-phase validation clears both fields and marks the observation contradictory. The example stops on known rejection and never uses validation acceptance to start dwell. Independent checked-wire and AckV-only application tests verify this additive public observation contract; it adds no wire field and does not change IQ Generator v1 permissions.
