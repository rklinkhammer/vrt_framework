# P14 next CIF0 batch readiness

Read-only audit, 2026-09-19. The next six CIF0 fields can proceed after the scalar batch gate and an internal API freeze. No new user architecture decision or missing normative document blocks bounded codec/native-value implementation. Deployment interpretation and complete GPS-sentence validation require the explicit inputs identified below; those limitations must remain visible rather than being guessed.

Reviewed: implementation-plan P14/M5 and coverage/evidence policy; architecture §3 and memory budget; protocol appendix §§3.2–3.3 and interpretation register; current `fields/arena.hpp`, `fields/packet.hpp`, `fields/types.hpp`, `codec/layout.hpp` and checked packet traversal. Normative source is the supplied local `AV49DOT2-2017-R2024.pdf`, inspected with PyMuPDF; page references below are **printed pages**, not PDF indices. No production file, test, or build was changed for this audit.

## Field boundaries and normative cautions

| Field | CIF0 bit | Structural extent | Native semantics and source |
|---|---:|---|---|
| Formatted GPS | 14 | Fixed11 words | Manufacturer OUI, embedded position-fix TSI/TSF and all three timestamp words, seven location/motion values. §9.4.5, pp141–144. |
| Formatted INS | 13 | Fixed11 words | Same representation/rules as GPS, with distinct field identity. §9.4.6, p144. |
| ECEF Ephemeris | 12 | Fixed13 words | Embedded fix metadata plus three position, three attitude and three velocity components. §9.4.3, pp138–140. |
| Relative Ephemeris | 11 | Fixed13 words | Same representation as ECEF; reference frame is supplied by the Packet Class. §9.4.9 Rule1 on p146 explicitly selects Figures9.4.3-2/3. |
| GPS ASCII | 9 | `2 + N` words | Manufacturer OUI and unsigned word count followed by ASCII sentences/null padding. §9.4.7, pp144–145. |
| Context Association Lists | 8 | `2 + source + system + vector + async + (A ? async : 0)` words | Four separate ordered SID lists and optional equal-length asynchronous tag list. §9.13.2, pp224–227. |

Embedded fix timestamps are not the enclosing packet timestamp. A zero embedded TSI/TSF means undefined content with the corresponding timestamp words still present; Rule9.4.5-6 requires all-ones words. Do not reuse a prologue helper that omits timestamp words when the code is zero. Preserve sample-count/free-running fractional encodings as their native integer quantity rather than interpreting every TSF as picoseconds. The unknown geolocation/ephemeris numeric sentinel is `0x7fffffff`; model unknown separately from a numeric reading. Signed fixed-point precision is retained exactly: angular quantities use22 fractional bits, position/altitude5, velocity/speed16. Apply each field's actual permitted ranges during semantic validation, and keep malformed reserved/padding bytes distinct from structurally readable but semantically invalid values.

OUI semantics inside a location field differ from packet Class ID assignment. The standard explicitly permits `0xffffff` for unknown manufacturer and permits part of the upper range only when the profile defines it. Do not invent a manufacturer or silently treat a profile-dependent code as a registered OUI.

The printed Figure9.4.9-1 on p147 resembles the11-word geolocation format, conflicting with the section's introductory statement and explicit Rule9.4.9-1 reference to the13-word ECEF format. The explicit rule provides a defensible implementation choice: use13 words, record the diagram anomaly in the coverage/interpretation note and use an independent literal vector. This does not require a new user policy decision. Similarly, the Speed Over Ground observation's stated upper range on p143 is not consistent with the signed32-bit Q16 representation; exact representable values and the normative representation take precedence over an impossible conversion. Do not manufacture extra bits or lose fractional precision.

Association count subfield limits are source/system511 each, vector65,535, async32,767; optional tags match async count. Validate reserved bits, exact field extent, packet extent, arithmetic overflow and work limits before traversing lists. These maxima cannot all coexist inside the maximum packet size. The reference materialization limit is1,024 aggregate association entries across all lists, including optional tag entries; tags also count as actual stored/visited units within the global4,096-unit traversal budget. Bounds are resource limits, not a reason to label a structurally valid larger field malformed.

## Current implementation gap

`SemanticArena<N>` is an append-only array of host `uint32_t` values. Its public `{offset,count}` slice has no association with a packet owner or generation. It is not yet connected to `SemanticValue`, `PacketSnapshot`, or the layout resolver. A bare slice or `span` copied into the existing snapshot would not create the immutable ownership promised by architecture §3.

The current snapshot stores fields/attributes inline and `freeze()` returns a bounded value copy. Scalar-batch `SemanticValue` is deliberately16 bytes. The historical capacity16 snapshot is roughly5.3KiB before any variable data; putting an11/13-word native struct directly into every alternative of the13-attribute `FieldEntry` would multiply storage throughout the four-field runtime and exceed existing budgets. The unused fixed16-word `VariableValue` is not a safe general solution for lists or snapshot lifetime.

`walk_layout` currently uses only descriptor constant word counts, and `layout_signature` includes field identities/attributes but no variable field shape. GPS ASCII and association lists need a checked value-dependent extent resolver. Decoder traversal must obtain an extent from validated wire headers without allocating or pretending the wire is a TLV stream.

## Recommended native arena and ownership contract

1. **Retain scalar defaults.** Extend semantic packet templates with an optional compile-time native-arena capacity, default zero. Use an empty storage specialization so existing scalar aliases and16-byte `SemanticValue` retain their size/behavior. Provide explicit arena-enabled aliases for the generic batch. Do not increase baseline IQ/transaction snapshot capacity or claim that the IQ profile now accepts these fields.
2. **Own arena contents in the snapshot.** The initial implementation should use inline bounded snapshot-owned native storage. An arena-enabled builder owns its current snapshot storage; `freeze()` copies the complete live native contents and metadata by value. Frozen snapshots survive mutation/destruction/reuse of the builder and caller inputs without shared mutable memory, reference counting, or hot allocation. The architecture's separately supplied arena is permission, not a requirement to choose a harder borrowed-lifetime design. A future external immutable-block owner can be added separately if copying proves expensive.
3. **Keep references compact and private.** A structured alternative can be an8-byte private native slice (`uint32_t byte_offset`, `uint32_t byte_count`) so the scalar variant can remain16 bytes. Field descriptors/native record headers carry the expected structure kind. Constructors are not public escape hatches. A raw `SemanticValue` containing another snapshot's slice must be rejected by ordinary `set_value`; typed setters must materialize/rebind the native value. Encoding resolves offsets only against the snapshot that owns them and verifies type, extent and initialized bounds. An arena slice is never a transport lease or a wire byte view.
4. **Store native values, not packet images.** Define typed `Geolocation`, `Ephemeris`, `GpsAscii` and `AssociationLists` values/views. Location types retain native exact fixed-point integers plus known/unknown tags and embedded timestamp codes/values. ASCII is native characters with explicit sentence length; SID/tag lists are host-native integers, preserving separate list boundaries, ordering and duplicate entries. OUI and count words are generated by the codec. If a byte arena holds trivial native objects, align allocation to their native alignment and read/write via safe copies into typed objects; do not reinterpret arbitrary byte/word storage as live C++ objects. Never alias network-endian input as typed native storage.
5. **Copy caller data synchronously.** Proposed user-facing forms are `set<Field>(typed_value)` for fixed structures and checked `set_gps_ascii(oui, characters, ...)` / `set_associations(lists)` for variable values. Borrowed caller spans are consumed only during the setter. Snapshot accessors return immutable views tied to that snapshot's lifetime, preferably rejecting access on a temporary snapshot. No returned view keeps the builder or an RxEnvelope alive implicitly.
6. **Make edits transactional across fields and arena.** Validate the complete requested value/attribute set and calculate aligned native capacity before committing. Build/repack a candidate from live values only; on success swap the bounded candidate and bump generation once. On failure preserve fields, arena used size, CIF/CIF7, old views of frozen snapshots and cached measures. Replacement/removal must reclaim obsolete values through bounded candidate compaction instead of consuming arena space forever. Builder-local views may be invalidated by mutation; frozen snapshot views may not.
7. **Treat capacity as an explicit policy.** Start with a modest named arena-enabled configuration and return `resource_limit` or `capacity_exhausted` when a legal value does not fit. Reconcile the combined snapshot, arena, transaction plan and temporary edit scratch against actual sizes. A1,024-entry aggregate uses4KiB before native headers; optional tags consume that same aggregate limit rather than receiving a separate allowance. It is not honest to promise every maximal field/attribute combination fits an8KiB transaction. Larger caller-selected generic capacities require an explicitly accounted configuration; no heap fallback is permitted.

An exact template spelling can be settled by the implementer after the scalar gate, for example `PacketBuilder<Kind,N,NativeBytes=0>` and corresponding `PacketSnapshot`, with the existing aliases retaining `NativeBytes=0`. The important contract is ownership, bounded copying, private checked references and retained scalar sizes; choosing a name or capacity is not a user-facing architecture blocker.

## Shared traversal and decode integration

Keep one shared traversal core for CIF/attribute ordering, offset advancement and budget accounting, parameterized by an extent provider. Supply checked native and wire extent providers selected by field descriptor, packet subtype/class and attribute; do not implement a second independent decode offset walk. GPS/INS/ECEF/Relative value bodies have fixed wire sizes but arena-backed native values; selectors still contain no value body, and diagnostics still occupy one32-bit word per selected field. GPS ASCII/list value extents must use checked header counts. Fully validate the complete packet before any application visitor, even when an early field is valid and a later variable field is truncated.

A `PacketView` continues to borrow checked wire bytes from its RxEnvelope. It may expose a typed structural geolocation/list view without allocating. Explicit materialization copies into an arena-enabled builder/snapshot and can fail independently on semantic/resource limits. Structural decode must not reject an otherwise readable negative/range-invalid field merely to reuse a builder, and must not claim it is a valid semantic value. Reserved bits, impossible counts and invalid padding remain framing/layout errors.

Include value-dependent per-field extent information in the layout signature and index validation, not just total packet size: two different variable field partitions can have the same total length. Attribute presence changes, list-length changes and replacement all invalidate generation/shape caches. Current-only support for this batch is acceptable if stated in the coverage matrix; unimplemented structured CIF7 shapes must return explicit unsupported-layout/semantic errors. Do not assume all13 attributes have the base value's extent.

## Inputs and decisions: what can proceed

**Routine implementation decisions, proceed internally:** owned versus optional external native arena (owned recommended), capacity templates, compact reference packing, native known/unknown wrappers, candidate compaction, immutable view APIs, registry extent callbacks, first Current-only coverage and exact size/work-budget tests. These follow existing architecture requirements and do not require user confirmation.

**Profile/deployment inputs needed only for interpretation or qualified emission:** GPS/INS altitude reference; Relative Ephemeris axes/origin and any ECEF transform; special manufacturer OUI meanings; association graph relationships, vector dimension and channel-tag mapping; GPS sentence format. Generic codecs can preserve these values and expose their unresolved meaning without inventing a deployment configuration. Association-list serialization is not automatic graph traversal, discovery or metadata cache merging.

**GPS ASCII semantic limitation:** the standard allows NMEA-0183 **or other valid GPS output formats**, so a universal complete-sentence grammar cannot be inferred from this PDF. Structural support can validate count/extent/ASCII/null padding and preserve the original sentence bytes. A typed API that claims complete-sentence semantic validation must require an explicitly supplied format validator or a separately qualified named format. Do not silently assume CRLF alone proves a complete valid sentence, strip interior nulls, normalize text, or advertise opaque byte preservation as sentence validation. Missing a deployment's sentence format blocks that semantic claim, not fixed geolocation/list codec work.

No unresolved I9 Array-of-CIFs issue is pulled into these six fields. P14/M5 remains incomplete until subsequent fields/attributes and the existing interpretation-dependent cases are separately handled.

## Required verifier evidence for the next batch

- Literal fixed11/13-word vectors with embedded timestamps differing from enclosing timestamps, all undefined timestamp forms, unknown numeric sentinels, signed fractional boundaries, OUI/reserved fields and semantic range failures.
- Variable-field zero/one/max configured counts, legal wire counts exceeding local budgets, checked count multiplication/addition, truncated list/ASCII tails, null padding and following-field offsets. Preserve list ordering, distinct lists and optional tag cardinality.
- No callbacks for any whole-packet structural failure; bounded work exhaustion classified distinctly; selectors and diagnostics use their actual body forms.
- Caller inputs changed/freed after setter; builder changed/destroyed after freeze; earlier snapshot byte-for-byte semantic content remains immutable. Reject cross-snapshot/private-slice misuse and malformed native extents.
- Atomic arena exhaustion, replacement/compaction and CIF7 failure rollback; cached layout invalidation for equal-total-size but different internal shapes; no hot allocation.
- Actual scalar/baseline size regression, generic arena size ledger, P02/P09 dependent checks and seeded variable-length fuzz corpus additions. No performance or full-standard claim based solely on round-trip tests.
