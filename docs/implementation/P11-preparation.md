# P11 preparation — unimplemented and unverified

This is a read-only handoff from the contracts agent, grounded in architecture §§7.1/12 and implementation-plan P11. It does not implement or qualify recovery. P11 remains gated on P10 PASS. No unresolved architecture decision was found; the gaps below require implementation hooks within already accepted policy.

- **Bounded asynchronous lifecycle:** `recover_stream(stream, RecoveryConfig, completion)` needs a stable per-stream operation record and explicit recovering/starting/running/faulted states. Configuration supplies a fresh paired SID, confirmed source/device state, an existing/replacement qualified clock binding, and evidence of peer provisioning/readiness. Validate all required known fields with existing descriptors; never restore last-requested values. Failure leaves Data stopped.
- **Close only the affected admission:** freeze new source generation and close command admission for that association. Shared AdmissionPool/Loopback `close()` is global and permanent, so it is inappropriate for ordinary per-stream recovery. Runtime/Engine/Manager need a local stop-admission and quiesce-all path that cancels/disarms pending operations through the existing execution state machine, retains original results/Acks, and does not construct synthetic wire cancellation requests.
- **Quiescence is separate from completion:** expose counts/status for active transactions, pending response sends, backend work, accepted transport I/O, and quarantined resources. Loopback provides `outstanding()` and explicit `prove_quiescent(token)`; Engine/Manager lack a local quiesce-all/active-count API, and Backend requires explicit quiescence/reinitialization evidence. Neither a synthetic failure, a deadline, nor zero callback-reference count alone proves that hardware stopped accessing memory.
- **Two-second graceful bound:** use the unchanged monotonic clock. Drain accepted I/O/results/responses while possible. At 2 s report outstanding work and fault/quarantine; immediate stop skips optional draining but has the same reclamation safety rule. Do not steal a writing completion slot. Safe reclamation may remain pending indefinitely until real evidence arrives.
- **Old identity remains old:** preserve the global RetentionStore and old full keys until terminal retention plus references permit expiry. Late callback storage must remain attached to its old generation; it cannot be repointed at a new Engine. Once backend/transport safety is established, detach unsent Data, old publication gates, RX waiting and Context history via the existing P09 generation hooks. App-held RevisionHandles, RetainedRx payloads and copied metadata survive independently.
- **Fresh wire identity and counters:** RouteRegistry and CounterRegistry currently offer only add-before-freeze. P11 needs bounded transactional installation of fresh Data/Context/Command SID mappings and fresh per-sender/SID/type counters. Preserve old-key response/duplicate tombstone handling as needed; never silently rewrite an old route into a same-SID new association. Peer readiness is explicit application evidence, not an invented wire reset packet. Install the confirmed initial revision and publish a qualified current-time full Context before new Data. Recovery does not reset the external epoch.
- **No recovery heap fallback:** Engine construction allocates setup-owned arenas today. Recovery must either reset an existing Engine only when all old resources/callbacks can safely be reused, or select a setup-preallocated generation bank. Old callbacks/references may pin a bank; bounded exhaustion rejects recovery rather than overwriting it or growing an uncharged heap. Charge any spare banks and tombstone capacity in the final Runtime budget. Application-supplied retained-handle destination storage remains external; Runtime-owned retained storage must be charged once.
- **Callback/domain lifetime:** lifecycle callbacks use bounded stable storage and run on the control domain. Preserve same-domain blocking-wait rejection. Do not tear down application callback contexts while accepted operations can still invoke them; after callback delivery is detached, remaining ownership/quiescence accounting must not call dead application state.

Required verification: S14/S15, missing peer readiness, same-SID rejection, invalid/unknown confirmed state, failed/stalled backend reinitialization, old callbacks after generation switch, app leases surviving recovery/destruction, repeated recovery with pinned banks, current Context before resumed Data, graceful deadline exactly at 2 s, synthetic completion without quiescence, and fresh counter domains without old duplicate re-execution.

### Safe execution-bank and route reuse strategy

A bounded implementation can reserve `Streams + RecoverySpares` execution banks during setup, with a small explicit spare count (one global spare is sufficient for serialized recovery). Each bank owns its Engine/Manager/backend state, copied association identity, stable callback context, and pending replies. The logical stream selects its active bank. Selecting a spare is not an assertion of backend quiescence: the old physical effects must still resolve, or explicit reinitialization must establish known state and quiescence before the new association starts.

A proven-quiescent old bank may remain logically draining while copied completion capabilities or retained responses still exist. Those capabilities retain their old storage and can never point into the new bank. New effects use the new generation and fresh SID. The shared RevisionStore ignores old-generation events; old transaction responses use the copied old bank identity and normal retained keys. If no safe spare is available, fail recovery with bounded resource exhaustion and keep Data stopped. Do not construct a new Engine on the hot path.

Reuse a retired bank only when all its Engine/Manager operations and scheduled cancellations are terminal, pending replies/transmission references are gone, backend quiescence is established, and completion/result capabilities cannot still access its reusable state. Completion slots must be free or retired, never stolen from writing/reading. Checked bank reinitialization updates confirmed state, backend bindings, timing pointers and association generation while preserving monotonically increasing operation/token generations; it must not reset old token namespaces to collide with stale capabilities.

Route callback contexts should be small separate generation records, so a bank can eventually retire without leaving a route pointing at its reused address. After old accepted I/O is drained, remove old Data/Context ingress routes; they must not dispatch into the new receiver. Old Command/Ack routes may remain as compact tombstones serving only exact retained identities and historical Controller observations. A fresh ordinary command on the old SID is rejected rather than admitted as a new-generation transaction.

Retire a tombstone route/counter slot only after its relevant retained transactions and Controller records have passed normal terminal retention and lost all references, plus the transport safety barrier. A fresh SID can then use that physical slot with a fresh counter domain. Never reuse the old SID merely because the local slot is free. Install all new paired routes/counters transactionally from a prevalidated candidate before changing the active bank. Capacity failure leaves the old routing state intact and the affected stream stopped. No read-only route pointer may survive the serialized install operation.

The existing ControllerRegistry keeps a bounded append-only relationship registry. The simplest safe P11 implementation can preserve this lifetime bound and reject recovery when relationship capacity is exhausted; it need not introduce an unbounded SID-history table or weaken the fresh-identity guard. If relationship retirement is added, its proof must include all associated retained Controller records and stale-wire identity exclusion. This is a bounded implementation choice, not permission for same-SID recovery.

Charge the actual spare-bank, tombstone and lifecycle-operation objects before Runtime allocation/registration. This note does not claim the extra objects fit the final 64 MiB aggregate; the implementation must calculate the layout and make an explicit budget transfer if required.

### Public lifecycle and wait results

Suggested public shapes are `RecoveryConfig{new_sid, confirmed_state, clock_binding_or_existing, peer_ready_evidence}`, `LifecycleCompletion{context, callback}`, `LifecycleStatus{phase, outstanding_effects, outstanding_io, quarantined, retained_application_leases}`, and a monotonic start/deadline in each bounded lifecycle operation. Separate input/admission rejection from asynchronous completion. Report peer-not-ready, unknown confirmed state, unsafe backend, insufficient capacity and graceful-budget expiration distinctly through bounded typed status/error values. Retained application leases are safe outstanding ownership, not a reason to revoke them or fabricate device uncertainty.

The current `wait(handle,timeout_ns)` checks that an observation can be queried, then returns `run_for(timeout_ns)` without testing whether requested evidence arrived. This does not satisfy architecture §11: successful pumping must not masquerade as transaction completion.

Use an explicit result such as `Result<WaitResult>` with `reason = requested_evidence_observed | wait_budget_expired | transaction_timeout` and an immutable observation/evidence snapshot. Add a read-only ControllerRegistry accessor for ordinary/cancellation phase completion instead of inspecting only its latest event. Poll before progress and after each progress step; return early once the requested evidence is complete. A validation-only or query wait can complete on its requested phase without claiming execution. Real execution confirmation still requires the existing real AckX evidence; validation, simulation, cancellation and local send completion cannot promote it.

The caller's wait budget is distinct from the transaction's original deadline. If the wait budget expires first, report that fact and leave the transaction pending with its original deadline unchanged. Do not automatically cancel or add a transaction-timeout observation. If the transaction deadline expires, preserve timeout with unknown remote outcome and retain late-response evidence without retroactively reporting on-time success. No-Ack and NACK-only silence remain unconfirmed. A zero wait budget is a checked poll, not unconditional success.

Same-domain blocking wait returns `would_deadlock` before any pumping, including calls from nested runtime callbacks. Production `run_for`/blocking wait may remain explicitly unsupported without a real executor/monotonic-clock binding; the isolated injected-clock helper must not be silently used as production wall-clock waiting. This limitation and the typed wait result are implementation behavior closure under existing architecture, not a new protocol decision.

## Agreed P11 transaction-hook split (awaiting P10 PASS)

The main implementer owns Runtime/lifecycle/banks/routes. The contracts implementer owns the following narrow transaction-layer hooks after release of the P10 gate:

- Append `Backend::quiescence` returning `BackendQuiescence{known, quiescent, pending}`. Missing evidence means unknown, not safe. VirtualBackend reports its explicitly modeled pending-work state; zero callback holders alone is not this evidence.
- `Engine::request_quiesce(OperationContext) -> Result<void>` closes new acceptance and cancels/disarms pending effect work through existing field outcomes. It requests draining; success does not mean quiescence. `progress` retains original requested Ack processing.
- `Engine::drain_status() -> EngineDrainStatus{active, running, responses, capability_holders, tickets_pending, backend, uncertain}` and `safe_to_reset()`. Reset safety requires no active logical work, undrained responses, holders or pending ticket states, plus explicit known backend quiescence.
- `Engine::reset_state(confirmed,new_generation) -> Result<void>` validates confirmed semantic state, permits explicit replacement rate/DPF/reference point for recovery, and resets fault/quiesce guards only after the safety predicate. It preserves operation/token/record generation counters and the bank's existing callback/effect/backend bindings. Runtime handles configuration/timeline and RevisionStore generation install separately.
- `Manager::close_admission()`, `request_quiesce(now)`, `drain_status(){active,scheduled_cancellations}`, and `reset_after_drain()`. Already accepted work still reaches retained terminal outcomes. Runtime counts its own queued Reply/transmission objects separately from Manager/Engine response ownership.
- `RetentionStore::association_retained(relationship)` and `ControllerRegistry::association_retained(relationship)` inspect the full relationship while ignoring only MID. Binding generation, peer/session generation, SID and both identifiers remain significant. Expiration is explicit through normal existing progress/expire, not hidden in the query.
- `RetentionStore::replay_existing(key,packet)` provides canonical exact retry/replay without creating a fresh ordinary or cancellation meaning. A closed Manager may use this path for old-generation tombstones; new old-SID effects reject.

Bank reuse additionally requires the Runtime's route/tombstone, retained-relationship, reply, transmission and physical safety predicates. Engine reset alone does not authorize reusing a wire identity or clearing retained Controller history. These APIs are agreed handoff names; no implementation or verification is claimed yet.
