# P14 recursive Array-of-CIF structural draft

Structural subset implemented in this isolated draft; the earlier native integration plan below remains deferred. No live production, other frozen draft or CMake edits. Sources: accepted protocol interpretation I9, protocol §3.3 bounds, current `walk_field_layout`/`decode_packet_bounded` and owned semantic arena, supplied VITA §9.3.1 pp130–131 and §9.13.1 pp222–223. This is the remaining CIF1/11 field; ordinary Array-of-Records fields retain their own layouts.

## Settled wire variant and remaining external qualification

I9 selects exactly three base words followed by **five** fixed CIF words (0,1,2,3,7), requires the header-size code7 and bitmap word0, and checks `total_words = 8 + record_words * record_count`. Do not apply the generic `3 + HeaderSize + product` formula here, invent two padding words, or detect a competing variant heuristically. Each record starts with an unconditional32-bit index, followed by selected fields in ascending CIF and descending bit order. The index is additional to any selected CIF field, not an Index List selector.

The five fixed masks are not an ordinary variable-length packet indicator prologue: their physical presence does not depend on CIF0 enable bits. A schema parser must accept this explicit fixed-mask input and use the ordinary descriptor/attribute legality checks without re-reading a synthetic packet header. CIF0 control/enable/change bits must never become record fields. This batch should document its handling of these nonfield bits explicitly, preserving their raw representation where structurally legal; it must not introduce an undocumented extra field or offset based on them. Shared known-mask validation remains necessary for reserved/unknown field selectors.

I9 is already an accepted implementation variant, so bounded structural support is implementable now. It remains **peer-dependent**. An explicit binding agreement is required before semantic use/emission for a peer, and an independent implementation or authoritative clarification remains required for an unqualified full-interoperability claim. That external qualification input is genuinely unavailable in this session; it need not block isolated structural tests, native representation or gated encoding of the accepted variant.

## API proposal

```
enum class ArrayCifDialect { vita49_2_i9_five_cifs_header7 };
struct ArrayCifDecodeOptions { ArrayCifDialect dialect; TimestampFormatBinding timestamps; };
struct TraversalBudget {
    size_t work_remaining;       // default4096, shared across whole packet
    size_t fields_remaining;     // default128, including nested materialized fields
    unsigned depth_remaining;   // default4 nested array levels
};
Result<ArrayCifView> validate_array_cif(Bytes exact_field, ArrayCifDecodeOptions,
                                      TraversalBudget&);
```

`ArrayCifView` is privately constructed after complete validation and borrows immutable bytes. It stores the fixed masks, record width/count, timestamp binding and dialect. Expose `record_count()`, checked `record(index)` and typed `index_number()`; nested FieldViews retain their absolute offsets and parent record path. Do not flatten nested values into an ordinary packet's unqualified FieldView list: identical FieldId/Attribute values in different records need distinct identities.

For callback traversal expose `visit_array(view, visitor, workspace)` only after the full field/packet validates. `ArrayPath` consists of at most4 `(record_ordinal, index_number)` pairs; ordinal preserves identity even if repeated application index numbers appear. The standard does not require sorted indices or prohibit duplicates, so generic structure validation must not invent either restriction. Runtime authorization and application record-index semantics are separate.

An explicit `ArrayCifAgreement` supplied by peer/class configuration gates semantic dispatch/encoding. Do not expose a boolean default that silently enables execution. Agreement is a configuration assertion under existing architecture, not cryptographic authentication; runtime's existing authorization/admission still applies. Selectors and diagnostics follow their existing zero-byte/one-word shapes and must not recurse merely because CIF1/11 is selected. Probability and belief retain their one-word CIF7 shape. Only base-shaped array attribute values recurse.

## One shared traversal, bounded work

1. Validate the available three-word header, then checked multiply/add for the total extent. Require header7/bitmap0, at least8 header words, exact extent and record_words>=1 whenever a record exists. Enforce wire12-bit count/width limits through decoding, then configured record_count<=256. A zero-record array may retain a structurally valid record schema and declared width; do not require a fabricated record to validate fixed header arithmetic.
2. Parse five masks once into the existing compact IndicatorPlan. Attribute selectors apply to each selected field through the same `attribute_shape` and descriptor provider as ordinary packets. Unknown field layout fails `unsupported_layout`; no skipping by guessed scalar size. Inherited TSI/TSF binding drives Age/ShelfLife in every record; no local timestamp header exists here.
3. For each record, bound its exact byte subspan first, read its index, and traverse field values using `walk_field_layout` refactored to separate indicator-prefix length from field-order traversal. The record walk starts at4 bytes after index and has no per-record indicator words. Every resulting extent must land exactly at `record_words*4`, including nested fields; shorter/longer record bodies fail. Variable-sized fields may differ in content, but every record must meet the declared width and shared outer schema.
4. Nested CIF1/11 invokes the same provider with the same mutable budget and one additional depth. Do not reset limits per record, field, attribute or diagnostic group. Use an explicit fixed stack of4 frames (or statically bounded recursion with equivalent measured stack use). Before entering a fifth nested array return `resource_limit` after validating its local declared size; there is no heap fallback.
5. Charge record-index traversal as one record unit, then existing scalar/structured field units; charge each nested occurrence once. Charge the field selection budget on each materialized field occurrence per record, not merely the common schema once. Attribute views have an aggregate capacity1664 under128 selected fields×13; selected-field budget and work budget are independent. The outer array field itself also consumes its field selection/work unit. A zero-record schema still receives bounded selector validation and cannot evade unknown-layout checks.
6. Preserve the current size-before-work rule: validate immediate declared extent/arithmetic before classifying its configured budget exhaustion. Do not inspect arbitrary descendants after a depth/work denial just to find a hypothetical deeper malformed field. Errors distinguish malformed/short input from supported-but-over-budget `resource_limit`.

Current `TraversalLimits` only contains association_entries/work_units and `shared_work` is optionally a pointer. It has no nested record/depth/field-state plumbing. Required additive change is a shared TraversalBudget cursor, initialized once by the outer decoder and borrowed through all providers. Keep the existing default16-field/64-view PacketView footprint and API: the generic128/1664 overload owns its explicit workspace, and recursion does not grow every baseline packet object. Shared layout changes require V-P02/P09/CIF7 regressions; this is an internal implementation choice, not a new user architecture question.

## Owned semantic builder and measurement

Add a typed `ArrayCifValue`/record-input facade with explicit dialect and a schema plus spans of immutable record inputs. The setter validates the entire candidate tree before committing. Deep-copy native headers, masks, record indexes and typed child values into the packet's optional bounded semantic arena; do not store foreign packet NativeSlice references, borrowed application spans or preencoded wire blobs as native semantics. Caller-created offsets are not an admissible setter input.

Internal native child offsets may be arena-relative compact references, with generation/provenance checks inherited from snapshot-owned access. All child references must remain inside the owning snapshot after copy/move. Use one transactionally rebuilt candidate arena; on capacity/validation failure, generation and original state remain unchanged. Capacity0 specialization remains unchanged in size and rejects typed array storage with a clear bounded-capacity error. The configured8KiB reference arena does not promise every legal256-record field fits.

Native extent provider and wire extent provider must share the same schema/order/attribute/depth traversal. Native measurement computes record extents and requires equal encoded word lengths, then derives the exact I9 total. Cached layout signatures must include array dialect, masks, record count/width and every nested variable-shape determinant, alongside timestamp binding and generation. Content-only scalar changes need not invalidate shape, but all candidate mutation still follows normal generation rules. Encoding preflights every field/budget/output before writes; peer agreement remains a separate required gate from successful measurement.

## Implemented structural subset and capability restrictions

`include/vita/codec/array_cif.hpp` provides explicit non-default-constructible `Options{Dialect::i9_five_cifs_header7, timestamps}`, transactional `validate(Bytes,Options,Budget&)`, privately constructed borrowed `View`, checked record spans and structural `visit`. There is **no** encode, native setter, agreement factory, application execution or peer semantic dispatch API. A successfully validated view is not peer agreement.

The coordinator approved these bounded I9 restrictions after the source review: all five masks are physically fixed regardless of CIF1..3 enable flags; permitted CIF0 change/enables are preserved and never become fields; reserved CIF0 bits0/4..6 reject. CIF7zero with bit7clear means implicitCurrent; nonzero CIF7 requires bit7set. Bit7set with zero CIF7, and nonzero CIF7 with bit7clear, return unsupported_capability. These latter combinations are unsupported by this explicit registered capability, not asserted universally malformed. CIF7 reserved bits remain invalid. Ordinary packet indicator parsing is unchanged.

The header uses the existing `IndicatorPlan`, field attribute shape/descriptor validation, wire structure extent and scalar attribute readers. The shared walker has one isolated additive prerequisite: a defaulted descriptor resolver lets CIF1/11 supply its metadata before the ordinary field registry contains that entry. `include/vita/codec/layout.hpp` is a shadow copy with only this hook; `layout-resolver.patch` records the exact additive diff and `shadow-base.sha256` the checked base. Promotion must apply the patch to the then-current live header, **never overwrite it with the shadow**, because the parallel CIF1 batch is adding other fields. Default resolver behavior is regression-tested with an ordinary Context packet.

Within each record, visits occur in ordinary field/attribute order; for a nested array, descendant elements are observed before their containing array FieldView (depth-first postorder). Record ordinal and raw32-bit index are retained in a bounded path. No duplicate/sorted-index policy is imposed. Validation has no application callbacks. View visitation is available only after complete validation and relies on the declared immutable backing-byte borrow; it repeats checked traversal with the original budget snapshot and does not consume the caller's cursor again. A visitor is a structural observation callback, not permission for device effects.

The packet-wide Budget shares fields/views/work across records, nested attributes and successive sibling validations; callers can carry it across warning/error groups. Failed validation leaves its original cursor unchanged. Root header/extent checks precede root field-budget charging; the parsed header is then reused. Nested array extent checks precede local depth/record-limit checks. Record units and scalar/structured extent units are counted once, and all current TraversalLimits metadata (including index_entries/records from the parallel CIF1 provider) propagates through the shared walker. The recursion is guarded at four array levels, with bounded stack-only local plans; there is no heap fallback. The enclosing array consumes one field selection plus its own work unit. Empty schemas/records are supported, but their fixed masks still reject unknown field layouts.
